# ECE 285 — Controlled Baseline and DP-SGD Rerun

## Objective

Rerun our Folktables ACSEmployment SGD and DP-SGD experiments to obtain reliable, reproducible results for our fairness–privacy study.

Our research questions are:
1. Does DP-SGD disproportionately reduce predictive accuracy across demographic groups?
2. How do accuracy and fairness change across privacy budgets?
3. Can subsequent LFR preprocessing and equalized-odds post-processing mitigate disparities?

**Focus on baseline training and evaluation for now. Do not implement fairness interventions or generate final report figures yet.**

## 1. Audit and preserve existing work

Review `proposal.md`, the data-processing and DP training logs, existing configs, preprocessing, training implementations, and results.

Verify the actual feature lists, label definition, splits, gradient normalization, sampling, initialization, and privacy accounting.

Preserve all existing results. Store new experiments separately under `results/controlled_v2/`.

## 2. Dataset and feature configuration

Use the existing California 2018 ACS Employment cohort.

- Main target: `Y = (ESR == 1)`.
- Keep `ESR` and `ESP` excluded from predictor inputs.
- Preserve existing age filters and missing-value handling.
- Use the existing fixed split manifest for the main comparison.
- Keep the final test set untouched.
- Fit preprocessing on the reference partition only.

Implement two feature policies:

**Primary — `include_sensitive`:** Include `SEX` and `RAC1P` as one-hot-encoded categorical predictors.

**Secondary — `exclude_sensitive`:** Preserve the original feature-excluded configuration.

Always retain original sex/race labels separately for fairness evaluation.

Use identical cohorts, splits, labels, and training settings across comparable experiments.

Audit household overlap, but do not change the split manifest without documenting the consequences and establishing a separate comparison.

## 3. Controlled training

Use the existing shared MLP architecture and settings:

- Input → 64 → 32 → 1, ReLU.
- SGD, learning rate 0.05, no momentum.
- 20 epochs, nominal batch size 512.
- Threshold 0.5.
- Fixed final-epoch evaluation.

Run ordinary SGD and DP-SGD at ε = 1, 4, 8.

Match architecture, initialization, optimization settings, data splits, update budgets, and preprocessing.

For DP-SGD, retain the existing Opacus clipping norm C=1, Poisson sampling, accountant, and delta policy.

**Important:** Ordinary SGD and DP-SGD cannot differ only by Gaussian noise under their current implementations. Therefore, also implement these non-private diagnostic controls:

1. Poisson-sampled SGD without clipping or noise.
2. Poisson-sampled SGD with per-example clipping C=1, without noise.

For the diagnostic comparison, match the sampling mechanism, optimizer updates, gradient normalization, and clipping implementation with DP-SGD as closely as possible.

Validate the clipping-only versus zero-noise DP optimizer updates using a deterministic unit test. Do not claim the controls are differentially private.

## 4. Repeated experiments

Start with five independent initialization seeds:

`[42, 123, 285, 2026, 2027]`

Run SGD and DP-SGD at all three budgets for both feature policies (40 main runs).

Use matched initialization seeds for paired comparisons. Independently randomize sampling/noise as appropriate for DP-SGD.

Save each run separately and make execution resumable.

After examining seed variability, expand important configurations to 10 seeds for the final analysis, especially if the differences between privacy budgets are small.

## 5. Metrics to collect

For every model and seed, record:

**Overall:**
- Accuracy, balanced accuracy, ROC-AUC, BCE loss.
- Actual and predicted positive rates.
- Privacy budget, delta, noise multiplier, clipping norm, steps, runtime.

**For every sex, race, and race-by-sex group:**
- Sample size, actual positive/negative counts.
- TP, TN, FP, FN.
- Accuracy, balanced accuracy.
- TPR, FPR, PPV, NPV.
- Predicted-positive rate.

**Fairness metrics:**
- Accuracy parity gap.
- Independence gap.
- Separation gap (retain TPR/FPR components).
- Binary sufficiency gap (retain PPV/NPV components).
- Group-specific accuracy loss relative to the matched SGD seed.

Calculate fairness gaps separately for each run before averaging.

Keep all nine race groups in detailed reports. For headline race comparisons, separately report groups with at least 500 development observations. Flag low denominators and preserve undefined metrics as missing rather than zero.
